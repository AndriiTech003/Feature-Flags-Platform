# 02 · Feature Flags Platform

> LaunchDarkly-lite: feature flags, процентные раскатки, таргетинг, remote config, эксперименты. **Главный продукт — SDK, опубликованные в npm**, и совместимые с OpenFeature.

## Зачем этот проект в портфолио

Флагман (01) показывает системный дизайн. Этот проект показывает другое:

| Навык | Как проявляется |
|---|---|
| **Проектирование библиотек** | Публичный API SDK, семантическое версионирование, changelog, tree-shaking, размер бандла |
| **Публикация в npm** | Реальные пакеты с provenance, типами, ESM + CJS, документацией. Редкий и очень сильный сигнал |
| **Детерминированные алгоритмы** | Бакетинг через хэш: один пользователь всегда попадает в одну группу на сервере и на клиенте |
| **Спецификация и совместимость** | Общий набор **conformance test vectors** (JSON), по которому проверяются и сервер, и все SDK |
| **Стандарты** | Провайдеры для **OpenFeature** (CNCF-стандарт feature flags) |
| **Streaming** | SSE-обновления правил, fallback на polling, работа офлайн |
| **Производительность** | Оценка флага за микросекунды локально, без сетевого запроса, с бенчмарками |

Проект небольшой (4–5 недель), но выглядит очень «взрослым».

## Компоненты

```text
feature-flags-platform/
├── apps/
│   ├── api/                 # NestJS — управление флагами, окружениями, сегментами, аудит, эксперименты
│   ├── relay/               # Fastify — раздаёт SDK правила (SSE + polling + ETag), масштабируется отдельно
│   ├── dashboard/           # React + Vite + TanStack Router/Query — UI управления
│   └── demo-shop/           # Маленькое приложение, которое использует SDK (живой пример)
├── packages/
│   ├── evaluator/           # ЧИСТОЕ ядро оценки флагов, 0 зависимостей, изоморфное
│   ├── sdk-node/            # Серверный SDK: локальная оценка, стриминг, события экспозиции
│   ├── sdk-web/             # Браузерный SDK: оценённые флаги для одного контекста, ≤ 5 KB gzip
│   ├── sdk-react/           # <FlagsProvider>, useFlag(), useVariation()
│   ├── openfeature-node/    # OpenFeature provider для sdk-node
│   ├── openfeature-web/     # OpenFeature provider для sdk-web
│   ├── conformance/         # JSON test vectors + раннер
│   └── contracts/           # zod-схемы ruleset'а и API
└── docs/
```

npm scope: `@<твой-ник>/flags-*` (например `@ashamrai/flags-node`).

## Главные инварианты

1. **Детерминизм:** `evaluate(flag, context)` даёт одинаковый результат на сервере, в Node SDK и в браузерном SDK. Проверяется общими test vectors.
2. **Монотонность раскатки:** при увеличении процента с 10% до 20% все, кто был в 10%, остаются включены.
3. **Независимость флагов:** попадание в 10% флага A не коррелирует с попаданием в 10% флага B (разный salt).
4. **Отказоустойчивость SDK:** если сервер недоступен, SDK возвращает последние известные значения или default и никогда не бросает исключение в код приложения.
5. **Аудит:** любое изменение флага в prod записывается с diff и автором. Для prod можно включить обязательное одобрение (change request).
